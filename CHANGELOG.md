# Changelog

Dates are 2026. The project was called Touch Master until 2026-10-07. The first tag is 0.1.0 (2026-10-08): everything under Unreleased below.

## Unreleased
- **Fixed:** tapping Shift and then a letter typed it in lowercase, and Caps Lock could never be turned on: the release of any keyboard touch, the Shift key's own included, cleared Shift (the check `len(gesture.active_contacts) == 0` is always true for keyboard touches). Confirmed on the Thor on 2026-10-09 with the real handlers and a fake keyboard (`42 down, 42 up, a tap`). Shift, Ctrl, Alt and Win now work the same way: a tap applies to the next key only, a double tap within `keyboard_caps_window_ms` locks it, a tap on a locked one releases it, and a modifier held with one finger covers every key typed with another (`bin/modifiers.py`).
- **Fixed:** a latched Ctrl / Alt / Win or Caps Lock stayed pressed after switching to Trackpad or Quick Controls, so clicks became Ctrl/Shift-clicks. Leaving the keyboard now releases every modifier.
- **Fixed:** in Split mode a pointer drag that crossed the split line stopped, because each move was routed by where the finger was, not where it landed. Touches now belong to the area they started in until they lift.
- **Fixed:** stopping the driver during the dim mirror's 0.75 s fade could leave the bottom screen dim with its recovery record already deleted: `stop()` restored the level while the fade went on writing lower values. It now waits for the fade, and the fade stops when asked.
- **Changed:** the header is taller (80 px, 64 px buttons, about 4 mm on this 3.92" panel instead of 2 mm) and the header, status ribbon, Quick Controls and trackpad hint use larger text sized from their boxes. The status ribbon used emoji the Thor's fonts do not have (they drew as empty boxes); it now uses short text labels.
- **Fixed:** key repeat and glide each used one shared stop flag, so a quick re-press or a new flick could revive an older worker (double repeat rate, two glides). Each now has its own. The repeat loop no longer presses Shift again on every repeat.
- **Fixed:** settings and mode changes from the Decky panel ran on the IPC thread while the touch thread used the same gesture state; one lock now serialises them.
- **Fixed:** a failed `select()` on the touchscreen ended the reader thread silently with the grab still held (dead bottom screen until a restart); it now takes the same restart path as a lost device.
- **Fixed:** a key or button whose release could not be written was still forgotten, so the shutdown release could not retry it. It now stays held until the release goes out.
- **Fixed:** the driver rewrote `config.json` with only its own keys, dropping `enabled` and anything else the plugin or manager wrote. It now merges into the file on disk.
- **Fixed:** `get_debug` reset the draw-time counters on every call, and the Decky panel calls it every 2 s. They are reset only when the request has `"reset": true`.
- **Fixed:** after `SYN_DROPPED` fingers already on the glass stayed invisible until they lifted. The driver now reads the slot table back with `EVIOCGMTSLOTS` (layout checked against the kernel's `include/uapi/linux/input.h`) and treats those contacts as new touches.
- **Added:** keyboard settings: key repeat delay (`keyboard_repeat_delay_ms`, 150-800 ms), repeat interval (`keyboard_repeat_interval_ms`, 20-200 ms) and the Caps Lock double-tap window (`keyboard_caps_window_ms`, 150-800 ms), in a new Keyboard section of the Decky panel. The defaults are the old hard-coded 350 / 60 / 350 ms, so nothing changes until one is moved.
- **Fixed:** the on-screen keyboard text was hard to read and the main symbol of two-symbol keys (1 / !) sat near the bottom of the key. Labels were fixed 14 px (main) and 11 px (corner, dim grey) on keys about 66-200 px across. They are now sized from the key (up to 34 px, corner symbol about 0.6 of that), the typed symbol is centred, the corner symbol is brighter, and every label sits on a shared baseline so letters with descenders no longer float higher. Drawing moved to `bin/key_render.py`.
- **Fixed:** after a restart during Steam's idle dim the bottom stayed bright (2026-10-08 22:09:03). The slider-drag guard (a dim needs 5 s without input) read the freshly started tracker's zero idle time as "input just now" and vetoed the start-at-floor dim. The guard now applies only once the tracker has been running for 5 s.
- **Fixed:** a second cause of the dip on wake (2026-10-08 22:07:18, still there after the boot-clock fix). Steam blanks the top panel (254 to 20 to 7) in about a second just before a suspend; the follower read it as an idle ramp and started the six-step fade, the system froze partway through it, and the rest of the fade and the restore ran after the wake. A fall with a single drop of more than a quarter of the range is no longer a dim. Steam's real idle ramp, a few percent per sample, still is.
- **Fixed:** the bottom screen dimmed for about a second after waking from sleep (2026-10-08 22:02:53 and 22:03:40: "dimmed ... top backlight falling, now 3%", then "restored ... top rose, now 100%"). The follower used `CLOCK_MONOTONIC`, which stops during suspend, so the last samples before the sleep and the first after it looked like one steep fall. It now uses `CLOCK_BOOTTIME`.
- **Fixed:** dragging the brightness slider dimmed the bottom screen for about a second: the top falling for 2.5 s looked like Steam's idle ramp, and a touch then restored it (2026-10-08 21:58:09). A fall now only counts as an idle dim after 5 s without input; Steam's ramp starts after a minute of quiet.
- **Fixed:** `scripts/deploy.sh` now removes a leftover `driver/` folder from the plugin directory. After a release-zip install, that folder held the zip's older driver files, and on every plugin load `main.py` copied them over the files `deploy.sh` had just put in place: on 2026-10-08 the Thor ran the old dim mirror after two deploys of the new one, and the mixed state left the bottom panel stuck dimmed. Mixing the two install routes on one Thor is not supported; to switch from the zip to `deploy.sh`, run it once.
- **Changed:** the bottom screen now follows the top panel's backlight instead of guessing Steam's idle timing. The old mirror read Steam's dim delay and tracked input itself, and its clock ran up to 55 s ahead of Steam's (2026-10-08: bottom dimmed at 19:37:33 and 19:47:50, the top ramp began at 19:38:28 and 19:48:00) because the physical controller `/dev/input/event7` is mode `c---------` and cannot be read. Now `bin/top_follower.py` watches the top backlight: a steady fall starts the bottom fade within about 4 s of Steam's ramp, a rise, a stopped slider move or a touch of the bottom restores it. Steam's delay and the AC fallback from the previous entry are gone (that fallback's reasoning did not hold: nothing dimmed for an hour on the charger with AC at 0). New tests include Steam's real ramp. A start while the top is already at its floor counts as a dim.
- **Added:** a release zip for the Armada Store. `python scripts/build-release.py` builds `release/Ratatoskr.zip` with one top-level `thor-input/` folder (the name existing installs use, so a Store install replaces a `deploy.sh` install) holding the plugin plus the driver under `driver/`. On load, `main.py` copies the driver files, the user unit and the launcher entries into the user's home when they are missing or differ, reloads the user systemd and restarts the service if the code changed. With `deploy.sh` there is no `driver/` folder and nothing changes. Tested on the Thor on 2026-10-08 by removing the installed driver, unit and launchers and installing the zip as the Store does: the files came back, the service was enabled and active, and Decky loaded the plugin. The optional narrow sudo rule is not installed by the zip. 4 new tests (they need Linux: `os.chown`).
- **Removed:** the Pinch to Zoom and Drag Lock switches, their `pinch_zoom_enabled` and `drag_lock_enabled` settings and the leftover engine state. Neither gesture was ever implemented (the switches were saved and nothing read them), and both had been switched off for causing accidental Ctrl presses and stuck left-button drags. An old `config.json` that still has the two keys is harmless: they are ignored.
- **Docs:** accuracy pass. Pinch zoom and drag lock were documented, and shown in the Decky panel and the manager, as working gestures, but `bin/engine.py` stores their switches and never acts on them (checked 2026-10-08: the only references are the setting plumbing and leftover state); the docs, the panel descriptions and the known-issues list now say so, and whether to finish or remove them is left open. The README's status note no longer says the idle-dim mirror has not been run on a device, and the fixed manager issues are gone from the known-issues list.
- **Fixed:** the glide could start from an old speed. The finger's velocity was only measured on steps that moved the cursor a whole pixel and was never aged, so a fast stroke, a pause and a lift (or a stroke that slowed to a crawl in sub-pixel steps) still glided at the speed from before it stopped. Velocity is now measured on every step, and a lift more than 0.1 s after the last measurement (kernel timestamps) glides nothing. Two tests that fail on the old code cover it.
- **Fixed:** the tray menu's **Stop** left the bottom screen with no driver at all. It wrote `enabled: false` and stopped and disabled `touch-master.service`, but never started Armada's stock `armada-bottom-screen.service`, which the manager's `--stop` and the Decky panel both do. It now runs the manager's `--stop` in a transient `systemd-run --user` unit, because stopping the service kills everything it started and the hand-back steps would die with it. Checked on the Thor on 2026-10-08: after the command the driver is inactive and disabled, the stock session is active and enabled, `enabled` is false; `--start` put everything back.
- **Fixed:** the Decky panel. Five switches (press-and-hold right click, three-finger middle click, pinch, three-finger swipes, drag lock) started as **on** in the panel's initial state and fell back to on when a value was missing, although the driver's defaults are off, so the panel could show and send the wrong state; they now start off. The 2 s status poll overwrote whatever you had just changed (the driver may not have applied it yet), so sliders and switches could snap back: a value you set now wins over the poll for 3 s. Every slider step sent its own backend call; the first goes out at once and then at most one every 120 ms with the latest value, and anything still waiting is sent when the panel closes. The mute and HUD switches flip at once, and a change to one of the two right-click settings refreshes the other, which the driver switches off. The helpers are pure functions with a Node test (`tests/test_panel_logic.cjs`). Installed and loaded cleanly by Decky Loader on the Thor on 2026-10-08; the controls themselves were not exercised by hand.
- **Fixed:** `config.json` is now written atomically. The driver, the Decky backend and the manager each rewrote it in place, so a crash or a power cut mid-write could leave it truncated and every setting reset to defaults. A temporary file next to it is flushed and renamed over it (`bin/atomic_json.py`, with a copy in `main.py` because only that file is installed in the plugin folder). The original owner and mode are kept: the Decky backend runs as root, and a plain rename would have left a root-owned file the user-level driver could not write. Checked on the Thor on 2026-10-08: a driver save keeps `armada:armada 644`, and the Decky copy run as root against a temp file owned by `armada` (mode 640) leaves it `armada:armada 640` with no temp file behind. Concurrent edits can still overwrite each other's keys (read, change, write); only torn files are fixed.
- **Fixed:** the standalone manager's controls and the IPC around them. The manager sent `set_brightness` and `set_debug_hud`, which the driver does not handle, and nested its settings (`{"settings": {...}}`) where the driver reads flat keys, so its brightness sliders, HUD switch and settings switches did nothing live; and the driver answered unknown actions with `ok`, so nothing showed it. The manager now builds its requests with `ipc_util` (checked by a test against the actions `thor_app.py` handles), its defaults match the driver's (`glide` on, `friction` 5: it used to write `glide` off and `friction` 7 into `config.json` whenever a control was touched), and it polls `systemctl` and the socket on a worker thread so the window cannot freeze.
- **Fixed:** IPC robustness. The driver read a request with a single `recv(4096)`, and an unknown action, bad JSON or failing handler left the client to time out or, for unknown actions, got a plain `ok`. Requests are now read to completion (up to 64 KiB, pieces allowed, 2 s limit so a stalled client cannot hold the server), and every failure gets `{"ok": false, "code": 303, "error": ...}`. Clients read replies until the driver closes the connection (Decky backend, manager). Checked live on the Thor on 2026-10-08: unknown action, bad JSON, a request in three pieces, a client that sends half a request and goes quiet. The old single `recv` was not seen failing; today's status reply is under 1 KB.
- **Fixed:** stopping or restarting the service skipped its cleanup. systemd sends SIGTERM and the driver kept the default action, which ends the process on the spot, so `cleanup()` never ran: a dimmed bottom screen stayed dim until the next start, and the shutdown lines never reached the log. SIGTERM and SIGINT now leave the main loop (through `GLibUnix.signal_add`), `cleanup()` is safe to call twice and every step is guarded, the IPC socket file is removed, and the touch reader no longer reports "touch device lost" when cleanup closes the descriptor under it. Found on the Thor on 2026-10-08: no `Daemon stopping` line at any of 26 restarts, four clean stop sequences after the fix.
- **Fixed:** closing the virtual devices with a button or key held could hang. `release_all()` held the bridge lock and then called `mouse_button()` and `key()`, which take it again; the lock is now re-entrant, with a test that fails on the old lock.
- **Fixed:** scrolling stopped working once the pointer had been still for 3 s, and again after 3 s of continuous scrolling. Game Mode's gamescope hides the pointer after `--hide-cursor-delay` (3000 ms on the Thor); pointer motion un-hides it, but wheel events neither un-hide it nor restart the timer, and a hidden pointer's wheel does not reach Steam (`refs/upstream/gamescope` `steamcompmgr.cpp` `checkSuspension`, `wlserver.cpp` `wlserver_mousemotion` / `wlserver_mousewheel`). A scroll or a button press sent after the pointer has been still for 2 s is now preceded by a net-zero one-pixel nudge (barry-launcher's `inputd` does this for scrolling). Button presses need it too: they do not restart the timer either, so tapping in one place, like a clicker game, lost the pointer after 3 s. `get_debug` telemetry counts them as `pointer_wakes`.
- **Added:** **Pen mode** for stylus use, set from the orange **Pen** button in the header (it cycles Off, Pen, Pen +) or the **Pen** section of the Decky panel. One touch moves the pointer and a second contact, such as a resting palm, is ignored. Two-finger scroll, three-finger swipes, pinch, drag lock and glide are off. A single tap does not click, because the pen landing often registers as a quick tap (seen in the touch log on 2026-10-08, 78 to 140 ms and 0 px, a fraction of a second before the real stroke); a **double tap** within 0.45 s and 60 px clicks, and a third quick tap clicks again for a double click. A **long press** right-clicks. A touch that starts in the right-hand strip scrolls up and down and one in the bottom strip scrolls sideways, with a dead zone for the landing wiggle, jitter rejection and speed-based acceleration. Each touch is logged with its duration, travel, position and the reason it did or did not click.
- **Added:** **Pen +**, the third pen setting, also keeps Game Mode's pointer visible and turns the scroll and press nudges off. It writes `~/.config/environment.d/50-ratatoskr-cursor.conf` with `HIDE_CURSOR_DELAY_MS=3600000`, which the Thor's `gamescope-session-plus` reads before applying its 3000 ms default and passes to gamescope as `--hide-cursor-delay`. That is a launch argument with no run-time setter, so it applies the next time Game Mode starts; until the running session has it, the nudges stay on, and the pen hint and the Decky panel say so. Leaving Pen + deletes the file. New: `bin/pen_mode.py`, `bin/session_cursor.py`, the driver action `set_pen_mode`, and `scripts/deploy-decky-panel.sh`, which installs only the Decky panel files (the plugin folder is root-owned).
- **Fixed:** deploying set the Thor's volume to 100% and raised Steam's volume toast. The deploy runs the test suite on the Thor, and one slider test (`test_requests_are_clamped`) called the real `wpctl set-volume`. Steam's own audio log showed the sink going to exactly 1.0 on each deploy from the first one carrying that test. The stats tests now block real commands and sysfs writes, override every hardware setter, and `test_zz_nothing_touched_real_hardware` fails if anything gets through.
- **Fixed:** the Mute button lagged. It ran `wpctl set-mute ... toggle` on the touch thread and then read the state back from a cache, so the button could show the old state. It now flips the shown state at once and a writer sets the mute state explicitly (`1` or `0`), so quick repeated taps cannot get out of step.
- **Fixed:** the Quick Controls sliders lagged and lost the finger on fast drags. Measured on the Thor on 2026-10-08: each backlight write through `sudo tee` took about 25 ms and the bottom slider did two per touch event on the touch thread, and every write forced a fresh stats sample (about 29 ms) on the next redraw. Writes now go to one background writer per control that always writes the newest value, the requested value is drawn immediately, stats are sampled once a second on their own thread, and a slider keeps following the finger that grabbed it even when the finger leaves the bar. `get_debug` reports `draw_ms_avg`, `draw_ms_max` and `frame_lag_ms_max` (read once, then reset).
- **Fixed:** the trackpad no longer gets stuck after pressing several fingers. Observed on the Thor on 2026-10-08: the digitizer sometimes never reports a finger's lift when several fingers are down (the kernel slot table keeps the contact for minutes), and a later finger can land in that slot and arrive as movement of the old tracking id. Four or more fingers at once are now ignored until all of them lift or go quiet for 1.5 s; contacts silent for 1.5 s are dropped on every frame and idle tick; a dropped contact that moves again is adopted as a new touch; the reader parses frames with timestamps from the kernel (`bin/touch_frames.py`), logs `SYN_DROPPED` and digitizer-versus-engine contact counts, retries a failed grab every 5 s, and exits for a restart when the device disappears.
- **Fixed:** three-finger swipes no longer fire on a 2 px move. The swipe's start position was never set (it compared against the screen corner, so any move sent Escape), and it could not trigger a second time. The start is now taken when the third finger lands, and a new swipe is allowed after a finger lifts.
- **Fixed:** quick cursor nudges no longer click, and taps no longer nudge the cursor. A tap is now under 0.25 s and 12 px of travel per finger (was 0.38 s and 36 px), and the cursor is held still while a touch could still be a tap. The engine now imports on machines without `fcntl`, so its tests run anywhere.
- **Added:** a `wake` action (and `touch_master_manager.py --wake`) that taps F24 through the virtual keyboard. Steam treats it as input: it restored a dimmed top screen within a second on the Thor and restarts the idle and sleep timers.
- **Fixed:** a dim left by a crash or restart is now reliably put back. Found on the Thor: the first write after a restart can fail with "Invalid argument", and recovery gave up. Recovery is retried every 5 s until it works, a `sudo` write that times out is checked by reading the value back (the timeout is 2 s, was 0.4 s), and write failures now log the reason.
- **Fixed:** the dim mirror's idle tracker listed input devices once at start, so after a boot it saw 3 of 5 (the virtual controllers appear later) and controller input counted as idle. It now rescans every 5 s, picks up and drops devices as they come and go, and never exits when the list is empty.
- **Fixed:** the bottom-screen idle dim was undone by Armada within seconds, because `armada-control` re-applies its saved bottom level every 2 s. The dim now also sets that saved level, records the pre-dim level for crash recovery, retries a failed restore instead of forgetting it, and treats a charger on the USB supply as AC (a charge limit makes the battery report "Not charging").
- Opt-in **bottom-screen idle dim** that follows Steam's dim delay (`mirror_dim`, `mirror_dim_floor_percent`), with a Decky toggle, a manager switch, `DBG-610`, an optional narrow sudo rule for backlight writes, and unit tests.
- Renamed **Touch Master to Ratatoskr** (display names only; the `touch-master` / `thor-input` runtime names are unchanged).
- Made the repo public-ready: no device address in tracked files (`deploy.sh` takes the host from an argument, `THOR_HOST`, `THOR_ENV_FILE` or a git-ignored `local/thor.env`), LF line endings pinned, `deploy.sh` restarts the user service after copying.
- Full documentation under `docs/`; corrected the README, which still described the removed edge-scroll feature.
